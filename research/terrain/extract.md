## 7. Extraction pipeline
Rule: **RAM is scarce, time is not.** Every step streams one batch at a time, writes results to disk and keeps nothing large in memory. Long runs (hours) are fine.

### Terrain extractor `src/tools/sn1_extract_terrain.py` (built 2026-11-22, spot cube; works)
Usage: `python -I src/tools/sn1_extract_terrain.py --center x y z [--size 500] [--tile 125] [--water x y z] [--out <Workspace>/sn1_extract/spot1]` (Unity metres). Pure numpy, no installs. Heavy job: takes the lock (`sn1extract`).
- **Pipeline:** decode overlapping batches (iterative octree stack) into one global uint8 type + density grid (grid 505^3 incl. 2-voxel margin, ~21.7 s) -> sparse surface nets (one vertex per surface cell = mean of edge crossings from `ComputeSurfaceIntersection`; quads split on the shorter diagonal) -> `make_manifold()` -> keep triangles whose centroid is in the cube -> split into x/z tiles by centroid -> one OBJ per tile `tile_<i>_<k>.obj`. Also writes `summary.json`, `preview_topdown.png`, `preview_section.png`. It meshes ONE global grid, so mesher chunk seams cannot exist; batch (160) and octree (32) boundaries only matter while decoding.
- **OBJ format:** vertices in UE axes, cm, absolute (`UE.X=100*unity.z, UE.Y=100*unity.x, UE.Z=100*unity.y`); `usemtl type_<n>` groups; winding: numeric (b-a)x(c-a) points out of the solid (front-facing in UE, left-handed). **Correction (VERIFIED 2026-11-22, `sn1terrain_import.py` NORMAL CHECK):** GeometryScript computes face normals with the opposite sign, so the UE importer MUST emit triangles as `a,d,b` (flipped); with `a,b,d` seabed normals came out Z -0.97, with `a,d,b` +0.97. Matches `research/terrain/legacy_lua.md` §3.
- **Spot1 run** (cube Unity x -1495.47..-995.47, y -517.33..-17.33, z -39.55..460.45; 64 batches 3..6 x 15..18 x 12..15, all present): 567,664 vertices, 1,131,984 triangles meshed, **1,115,977 triangles kept** across 16 tiles of 125 m (tiles 0_0..3_3 in `<Workspace>/sn1_extract/spot1/`; the old overview row said 1,115,656). Total 39.8 s (decode 21.7 s, mesh 24.0 s cumulative). Peak RAM well under 2 GB.
- **Self-checks (VERIFIED 2026-11-22, run output):** spot (-1245.47,-267.33,210.45) is 0.509 m above the extracted surface (ray hit y -267.839) and outside solid; water point 15.67 m above the surface; 4,752 seabed triangles near the spot have mean UE nz 0.864 (92.6 % nz > 0.5); no NaN vertices. Tile gap check: 1,675,371 edges, 4,765 single-use edges, 4,514 on the cube's cut border (expected), 251 interior open edges (same rounding artifact as the origin set below). Previews: height map -387 m (west) to -92 m (east), seabed rising to the east, a pit pair left of centre, a ridge below the marked spot.
- **Ground truth VERIFIED (2026-11-22):** `src/tools/sn1_compare_terrain.py <extract_dir> <collider.obj>` against the in-game raycast heightfield `<Workspace>/reports/sn1_spot1_shots/spot1_terrain.obj` (3,668 vertices, Unity m, inside the cube): distance to nearest extracted triangle **mean 0.029 m, median 0.017 m, p95 0.092 m, max 0.362 m** (target < 0.5 m); writes `compare.json`. (The 481k-vertex `spot1_terrain_render.obj` was not compared; the script loops per point in Python, so subsample it first.) State: **VERIFIED 2026-11-22 (offline)** for spot 1, see `research/sn1/README.md`.
- **Open:** type id to material table; SN1 `Relax` smoothing and blocky mesher not ported (surface nets is smoother, same surface within about 0.1 m); decimation/Nanite size of 1.1 M triangles per 500 m cube was tried only for the two cubes.

- Gotcha: the pod XY (0,0) lies exactly on the seam of tiles 1_x/2_x and 1_y/2_y; a vertical line trace exactly along x=0 or y=0 slips through the seam, offset it by a few cm.
- **Triangle holes: SOLVED (2026-11-23).** Root cause: the surface-nets mesh is NON-MANIFOLD: 4 quads share one edge where a cell face is ambiguous (checkerboard). Index-based check: **1,445 edges shared by 4 triangles, 0 other bad edges, 6,860 open edges all on the cube border, 0 interior open edges.** GeometryScript `append_buffers_to_mesh` (DynamicMesh) refuses the 3rd and 4th triangle of an edge, so about 2 triangles per bad edge vanished from render and collision (up to about 2.9 k triangles). The old gap check was blind to it (4-use edges balance +1+1-1-1 = 0). The "535 interior open edges" were position-key artifacts (OBJ rounded to 0.01 cm collapses 1,178 near-zero-area triangles into index-degenerate ones); they stay in the output (removing them would open cracks).
- **Fix: `make_manifold()`** in `src/tools/sn1_extract_terrain.py`, right after `surface_nets`: every (triangle, corner) is a node, fans are joined across good edges, the two direction pairs of each bad edge are matched (preferring the pairing consistent at both endpoints) and joined at both endpoints, each remaining class of a vertex gets its own copy at the same position (geometry identical). New index-based `topo_check()` in the summary (`selfcheck.tile_gap_check.topology_index_based`): assert `interior_open_plus_nonmanifold` == 0. **Real extraction VERIFIED (2026-11-23, `<Workspace>/sn1_extract/origin_fix1/summary.json`, log `<Workspace>/reports/origin_fix1_extract.log`):** about 35 s; `make_manifold {'bad_edges_per_pass': [1450, 4, 0], 'vertices_added': 1527, 'final_bad_edges': 0}`; `nonmanifold_edges` 0, `interior_open_edges` 0, `interior_open_plus_nonmanifold` **0**, open edges 6,862 (all near the border); triangles 1,908,950 (identical); vertices 957,871. Old output kept as `<Workspace>/sn1_extract/origin_prefix`; `origin` now holds the fix1 data (importer reads `sn1_extract/<set>`). Importer logs `WARNING <tile>: dynamic mesh kept N of M OBJ triangles` and a total "lost" line (must be 0). In-game result: `research/terrain/checks_origin.md`.
- **Texture streaks (cause found 2026-11-23, not fixed):** `sn1terrain_import.py` uses planar UVs `(X,Y)/UV_CM` from world XY only, so near-vertical faces project along Z and stretch into vertical streaks. Needs triplanar projection in the material or per-triangle dominant-axis UVs (vertex splitting); UNTESTED, not cheap.
- **Saw-toothed cube edge (user F1 `bugshots/20261123_181716_004`, +x face at SN1 x=249.6): not a chunk seam.** Binned midpoints of the 1,445 four-triangle edges, the 535 position-keyed edges and the 1,178 degenerate triangles by voxel index mod 32 and mod 160 per axis: the fraction within 1.5 voxels of a plane is at or below uniform expectation (mod 32: 0.05 to 0.09 vs 0.094; mod 160: 0.00 to 0.012 vs 0.019), so the chunk-seam hypothesis FAILED (2026-11-23). The saw-tooth is the extractor's own cut: `keep = centroid inside cube` drops whole triangles, never clips; at the +x face 410 triangles straddle x=250 and are removed whole (0 kept have centroid >= 250); kept vertices reach 0.40 m past the plane. VERIFIED (2026-11-23, OBJ data). Not fixed (user decision: no clip, `checks_origin.md`). Cheap fix if wanted: clip triangles to the 4 side planes (Sutherland-Hodgman) and apply the same clip to the 125 m tile split; UNTESTED.

## Whole-map pipeline (plan, UNTESTED) — OPEN (2026-11-22)
**Stage 0: learn the formats (no game run).** Decompile `Assembly-CSharp.dll` with `ilspycmd`, one type at a time (`-t OctNode`, etc.), not the whole dll. `ilspycmd` needs `dotnet tool install -g ilspycmd`; the .NET 8 SDK is present. Ask the user before installing. Read the answers to the open questions in §4 and §5.

**Stage 1: offline converter (Python, outside the editor).** Writes to `<Workspace>\sn1_extract\`; never commit its output.
1. **Terrain.** For each non-empty `.optoctrees` file: decode into a 160^3 type/density array plus a 1-voxel border from neighbour files; mesh with the SN1 algorithm once known (surface nets is the fallback); decimate (error-bounded, flat areas first); write a per-batch mesh file (UE axes/cm, indices, material id per vertex or triangle). Peak RAM about 8 MB of voxels plus mesh buffers, sequential, no multiprocessing. Order: one batch (12-18-12, Safe Shallows), then the y 18/19 layers around the lifepod, then everything.
2. **Objects.** Stream each cells/batch-objects file; resolve ClassId -> prefab path through `prefabs.db`; compose parent transforms into world transforms in UE axes (§3); write one CSV/JSON-lines file per batch: `classId, prefabPath, ue_location, ue_quat, ue_scale`; `EntitySlotsPlaceholder` and atmosphere volumes to separate files.
3. **Biomes.** Convert `biomeMap.bin` plus the atmosphere volumes into SN2 biome-region boxes/volumes data.

**Stage 2: modkit editor import (editor Python through `src/modkit/tools/ue_run.py`, long-running, low RAM).**
1. **Terrain meshes.** Per batch file: `append_buffers_to_mesh`, then `create_new_static_mesh_asset_from_mesh` with Nanite (path VERIFIED in `research/terrain/legacy_lua.md` §3, about 7.5 s per asset). Save, unload and GC after every N assets; restartable (skip existing assets). A few thousand non-empty batches x about 10 s = many hours (acceptable). Option: merge 2x2 batches into 320 m assets.
2. **Placement.** In `L_SN2World` (`/Game/Mods/SN2EmptyWorld/L_SN2World`), or better in World Partition / streamed sub-levels so the whole map is never resident at once (open question). Objects become instanced static meshes per prefab, about 200 k real objects after removing `CellRoot` and the slots.
3. **Cook and package** with `cook_install.sh` (IoStore).

**Object meshes (decision needed).** (a) map SN1 prefabs to similar SN2 assets with a hand-made table (keeps the SN2 look, no asset extraction); (b) extract SN1 meshes and textures from the Addressables bundles with UnityPy (`pip install UnityPy`, ask first) and import them as new assets (faithful look, more work, same legal limits as terrain). Terrain materials need the same choice (SN1 textures or SN2 terrain materials). The later per-prefab tooling is in `src/tools/sn1_extract_prefabs.py` / `research/terrain/import.md`.
