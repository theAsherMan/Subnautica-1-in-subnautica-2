## Screen-identity menu navigation (OS mode; implemented 2026-11-19)
Replaces blind step-order clicking in `src/tools/autotest_driver.py` (`do_steps`) for `new_game`, `load_game`, `quit_game`.
- **Fingerprints** (`src/tools/autotest_screens.py`; data `plans/screens.json`, numbers only, ~115 kB, no images; boxes in `plans/screen_labels.json` `boxes`): per screen a fixed UI box (1920x1080 coordinates) -> grayscale -> downscale 8x (BOX) -> subtract gaussian blur (sigma 1.5 px) = high-pass -> normalise; reference = mean over all labelled shots of that screen; distance = 1 - NCC. The high-pass removes the panning cave/ocean background and fade brightness. Screens: `notice`, `title`, `main_menu`, `save_list`, `create_game`, `slot_menu`, `slot_pane`, `pause_menu`, `exit_confirm`; anything else (loading screen, in-game) = `unknown`. `slot_pane` before and after the Default Save click are one screen (the step `load_pick_default_save` uses `settle`).
- **Thresholds:** accept distance <= 0.40, runner-up at least 0.30 farther (in `screens.json` `thresholds`).
- **Masks (2026-11-19):** `screen_labels.json` has `masks` (`save_list`: rect 990,455-1470,730 = the save rows; zeroed after the high-pass, `feature(..., mask=)`), `extra` (single stall shots as labelled samples) and `not_o` (waypoint shots that really show a menu). The save rows grow with every run and had pushed the `save_list` distance to 0.60 (FAIL_MENU); left menu column, the NEW SINGLE PLAYER GAME / CONTINUE PLAYING buttons and the box layout stay in the fingerprint. A growing save list is tolerated.
- **Labels:** the NN-th `menu_NN` shot is taken AFTER step NN's action, so it shows the NEXT screen; the last shot after `exit_without_saving` is the loading screen (`o`). Label every new run in `screen_labels.json`.
- **Tools:** `python -I src/tools/autotest_screens.py build <Workspace>/autotest` (rewrite `screens.json` from the labelled run folders), `... check [--loo]` (confusion table), driver subcommands `screens-build`, `screens-check`, `identify [FILE]` (live screen if no file).
- **Offline validation (VERIFIED 2026-11-19, 448 shots, 23 runs, after the masks):** 0 misidentified, also with `--loo`. Own screen max distance 0.000-0.134 (`pause_menu` 0.201 leave-one-out); nearest other menu screen min 0.745 (`save_list` vs `main_menu`); in-game/loading shots vs any reference min 0.843; notice vs title 0.907 / 0.797, so the two CONTINUE buttons at (960,930) are never confused. 244 non-menu shots all `unknown`. Only 2 `slot_menu` shots exist (weakest reference).
- **Driver logic per step** (`menus.json`: `expect`, `actions`, `settle`, `post_log`, `done_log`, `post`): (1) `settle()`: wait (<= 90 s first step, 45 s later) until the same identity was seen in 3 polls >= 0.8 s apart and the box luminance moves < 1.5 (a fading-in screen is identified early but ignores clicks); unknown = keep waiting. (2) Identified screen is a later step's: skip ahead (notice -> main menu skips `title_continue`); an earlier step's: go back (max 4); anything else: `FAIL_MENU`. (3) Act; poll every 0.4 s up to 10 s until the screen is identified as something else in 2 consecutive polls (or the log condition is met). (4) Still the same screen = act again, max 3 attempts, then `FAIL_MENU <screen> <what was identified>`. Every identification is logged (`identify:` / `stable:` / `poll:` with best/second distance). `click()` approaches the target from 37 px / 23 px away (hypothesis UNTESTED: the cursor already sat on (960,930) from the notice click, so the title CONTINUE may never have got a hover). `load_confirm` alternates Enter / click CONFIRM (960,687) / Enter.
- **Quit path:** `escape_menu_open` expects "no known screen" and needs `pause_menu`; `exit_without_saving` succeeds only when UE4SS.log shows a new `[SN2AutoTest] WORLD L_ClientLobby` line (game log `LoadMap: /Game/Maps/L_ClientLobby?MenuReturnReason=Quit`); then `main_menu` must be identified before `main_quit`; after `main_quit` the process must exit within 25 s, else stall artefacts + `QUIT_FAILED` + `RESULT FAIL_QUIT` (never a plain DONE).
- **In-game result (VERIFIED 2026-11-19, `autotest_retry.sh smoke`, run `20261119_170405_smoke`):** `RESULT DONE` first attempt, `RETRY_SUMMARY attempts=1 crashes=0 menu_fail_retries=0 final=DONE`, 8/8 shots, exit through the menu, no `FORCED_KILL`. The re-click, skip and FAIL_MENU branches are only simulation-tested (offline, mocked clicks with real screenshots, title ignoring 2 clicks: LOGGED).
