**How to run** (`run_in_background: true`; nobody may touch the PC in OS mode):
- `bash src/tools/autotest_retry.sh --timeout <s> <plan>`: up to 3 attempts, retries only after `CRASH`, prints `RETRY_SUMMARY plan attempts crashes final`. One attempt: `bash src/tools/autotest.sh --timeout <s> <plan>`. `--timeout` is mandatory.
- `autotest.sh` steps: abort if the game runs; `backup_saves.sh`; install SN2AutoTest + SN2Census (+ plan `mods`); `autotest_driver.py arm` writes `<ue4ss Mods>/SN2AutoTest/run/active_plan.lua`; delete `UE4SS.log`; launch; start `autotest_driver.py run <plan.json>` in the background; poll every 5 s.
- Verdicts: driver finished = its `RESULT` line (taskkill after 60 s); game gone and driver `RESULT DONE` = `DONE`; game gone otherwise = `CRASH` (new folder in `%LOCALAPPDATA%\Subnautica2\Saved\Crashes\` or new `ue4ss\crash_*.dmp`) or `EXITED`; `TIMEOUT`. Driver results: `DONE FAIL_LOBBY FAIL_NOPAWN FAIL_FOCUS FAIL_MENU FAIL_QUIT FAIL_DIALOG FAIL_LUA_LOAD FAIL_RESPAWN FAIL_EXCEPTION`.
- Exit codes (VERIFIED 2026-11-22): 0 = `DONE` (shots complete, or at least one DIED waypoint); 1 = any other result, or DONE with missing shots; 2 = pre-flight refusal (bad plan or `--input`, lock not acquired, game already running, arm failed). The EXIT trap `on_exit` writes the real status to `<Workspace>/autotest/<run>/exit_code.txt` and releases the lock only if autotest.sh took it. Exit 255 happened once (cause UNCONFIRMED; the old cleanup `Get-CimInstance ... Where CommandLine -match 'autotest_driver' | Stop-Process` could match its own powershell); replaced by `kill_driver()` (only `python.exe` whose command line has `autotest_driver.py run`); two later runs exited 0. If 255 returns, read `exit_code.txt` first.
- Never edit `autotest.sh` while a run executes (bash reads scripts incrementally).

**Plan format** `src/mods/SN2AutoTest/plans/<name>.json`: `{name, worldLevel (path or null = the ModActor's L_SN2World), start "new"|"load", loadSlot, settleSeconds (15), mods:[..], waypoints:[{name, offset:[x,y,z] cm | absent}]}`.
- Offsets are added to the first `BP_StaticLifepod_Surface_C` location (works in L_Main and L_SN2World); no offset = recorded settled spawn.
- `plans/menus.json` holds the button centres (named steps), the engine steps and the mouse calibration. `plans/screens.json` and `plans/screen_labels.json` feed the screen fingerprints.
- The driver converts waypoints and worldLevel into `run/active_plan.lua`. Lua renames it to `active_plan.consumed.lua` on load (a crash never leaves it armed). No plan file = `[SN2AutoTest] idle (no plan)` and no hooks.
- `mods`: extra mods the plan needs, e.g. `"mods": ["SN2BugShot"]` (plans bugreport, bugshot, tadpole; 2026-11-24).

## Hidden desktop is the default; mandatory test timeouts (2026-11-22)
- `autotest.sh` / `autotest_retry.sh` run on the hidden desktop SN2Test by default (engine mode; user input cannot reach the game). Opt out: `--visible` or `SN2_HIDDEN=0` (engine-mode run on the user's desktop via `launch_game.sh`). `--input os` requires `--visible`. Steam precondition: `ensure_steam`.
- **Options:** `--timeout <s>` REQUIRED (whole run, launch to game exit; counts from run-folder creation, so a tiny timeout can fire before launch work finishes; keep it generous); `--check <s>` optional check period (recorded in `<run>/run_info.txt`, default for `test_wait.sh`); `--timeout-reason "<why>"`; `--after-fix "<what>"`; `--visible` / `--hidden`; `--precheck-only`; `--retry-menu`; `--keep-world`. `autotest_retry.sh` forwards all of them (`--timeout` is per attempt) and runs the refusal checks before it takes the lock. Do not pass unknown flags such as `--help` to `autotest_retry.sh` (they become plan args).
- **Refusals** happen before the heavy lock, install or launch. Exit codes: 8 no/invalid `--timeout`; 9 raising the timeout after the plan's last run ended TIMEOUT without `--timeout-reason`; 10 last two runs of the plan both TIMEOUT (override `--after-fix`; does not waive the reason rule); 6 Steam not ready; 2 other (bad plan/mode, game already running, lock not acquired); 7 hidden launch failed (game not running 60 s after launch). Any non-TIMEOUT verdict resets the count.
- **Timeout behaviour** (`autotest.sh` loop, polls every 5 s): at `--timeout` the verdict is TIMEOUT; the phase reached (last `step` / `waypoint` line of driver.log) goes to driver.log, summary.txt and the tsv; driver killed; `stop_game` (`autotest_lib.sh`) asks for a clean quit (`autotest_driver.py quit`: main_quit click via the command channel, WM_CLOSE fallback), waits 20 s, then force-kills `Subnautica2-Win64-Shipping.exe` through the FORCED_KILL path; the holder is ended; `RUN DONE TIMEOUT` goes to `<Workspace>/autotest/hidden_desktop_status.txt`; normal collection and lock release follow. Internal driver waits (lobby 300 s, per-step settle) end with FAIL_* verdicts; there is no second overall driver timeout. The "game never started" check (300 s, EXITED) applies only when `--timeout` > 300.
- `<Workspace>/autotest/timeouts.tsv`: one row at EVERY run end (aborted runs: verdict `ABORTED_rc<n>`): `datetime, plan, timeout_s, verdict, phase_at_end, run_time_s, run_folder, reason`. Header starts with `#`. Test override: env `SN2_TIMEOUTS_TSV`.
- `bash src/tools/test_wait.sh [--run <dir>|latest] [--for <s>]`: blocks until result.txt exists or the period (default: the run's check period, else 60 s) elapses; prints verdict/"running", elapsed vs timeout, phase, shot count + newest shot, last 8 driver.log lines. Exit 0 finished, 1 running, 2 no run. Never extends the timeout.
- `bash src/tools/autotest_stop.sh [--run <dir>|latest] [--reason ..]`: writes `<run>/stop_request.txt`; the run's loop then does clean quit, 20 s, FORCED_KILL, verdict STOPPED. If result.txt is absent after 60 s it stops that run's game process and holder itself.

## Retry policy and crash-during-load classification
- `autotest_retry.sh` retries only after `CRASH` (up to 3 attempts). FAIL_MENU is retried once only with `--retry-menu` (default off). If a plan says "retry only on CRASH", stop a second attempt with `autotest_stop.sh --run <dir> --reason ".."` (LOGGED 2026-11-22, run `20261122_164213_spot1`).
- `autotest.sh` turns any non-DONE/STOPPED verdict into CRASH when a new dump was copied to the run's `crash/` or `Subnautica2.log` has `Spent too much time waiting for FinishDestroy`, `AbortInsideMemberFunction`, `Fatal error` or `LowLevelFatalError` (`crash reason:` line in summary.txt). LOGGED (2026-11-22, run `20261122_164700_spot1`: TIMEOUT reclassified to CRASH, then the CRASH retry gave DONE; run `20261122_163326_spot1` crashed during map load and looked like FAIL_MENU).
- A crash while the map loads can look like FAIL_MENU or TIMEOUT: check `crash/*.dmp` in the run folder before theorising about menu navigation.
