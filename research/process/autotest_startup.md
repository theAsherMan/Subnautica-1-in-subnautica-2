## Start-up hang (the game's unclean-exit dialog; cause VERIFIED 2026-11-18 from the logs of every run + the tester's report of the dialog text)
- The game has a crash watchdog (`LogUWECrashWatchdog`). While running it keeps two mark files in `%LOCALAPPDATA%\Subnautica2\Saved\`: `running.dat` (removed on a clean exit) and `beforelobby.dat` (removed once the lobby is reached). At start-up it logs `Warning: Running mark exists when starting, last exit was unclean` and/or `Warning: Lobby mark exists when starting, last load did not reach the lobby`.
- **When both marks exist** the game opens a modal Windows dialog and the main thread waits on it (`ThreadState=Wait WaitReason=LpcReply`, black game window). In the log it sits between `LogMercuna: Display: Unreal Engine version: 5.6.1` and `LogGameInput: GameInputBase module startup...` (normal gap ~60 ms). Only the running mark (`beforelobby.dat` absent) = warning, no dialog.
- Loop: game force-killed before the lobby (`FAIL_LOBBY` -> `taskkill /F`) -> both marks stay -> next launch shows the dialog -> nobody answers -> `FAIL_LOBBY` -> kill again.
- **Dialog (VERIFIED 2026-11-18, `dialogs` subcommand + screenshot):** top-level window of the game process, class `#32770`, title `Error`, children `Button` + `Edit` (the message is a read-only **Edit**: `GetWindowText` returns empty; the driver reads it with `WM_GETTEXT` via `SendMessageTimeoutW`). Text: "Your game might not have exited correctly the last time you played. Verify your system meets the minimum requirements, and if this persists, update graphics drivers, or try resetting or lowering the game settings." **Only one button: `OK`** (screen rect (1091,586)-(1164,610)); no "reset settings" option exists.
- **Rule:** the harness exits the game cleanly whenever it can, and detects this dialog after launch and dismisses it only through a button that just continues (`OK` / `Continue` / `Close`). It must never pick a reset / lower-settings option (capture resolution must stay 1920x1080). Never delete the mark files (Saved is off-limits).
- **Driver behaviour (`src/tools/autotest_driver.py`):** `find_game_dialogs()` lists visible `#32770` top-level windows of the game pids (title, texts, buttons with `&` removed, hwnd, rect); subcommand `dialogs` prints them. `run_plan` checks each second while waiting for the lobby line (300 s): prints `[driver] DIALOG title=.. text=.. buttons=[..]`, saves `shots/menu_00_dialog.png`, clicks a matching button, prints `[driver] DIALOG_DISMISSED <label>`, waits up to 5 s. No such button = `RESULT FAIL_DIALOG buttons=[..]`, exit 4. At most 3 dialogs per run.
- **Clean-exit policy:** after `FAIL_LOBBY`, `FAIL_NOPAWN` or `FAIL_EXCEPTION` the driver closes the game itself (`clean_exit`): pawn possessed -> the `quit_game` menu steps; otherwise `Alt+F4`. Wrapped in try/except, never hides the RESULT line. `autotest.sh` still waits 60 s before `taskkill`; every `taskkill` of a running game is logged as `FORCED_KILL <reason>` (`forced_kill.txt`, copied into `summary.txt`). `autotest.sh` writes `marks_before.txt` (presence + mtime of both marks before launch).
- **VERIFIED (2026-11-18/19):** `dialogs` with no game: `done: 0 dialog(s)`; `launch_game.sh` + `taskkill` ~9 s later left both `.dat` files; run `20261118_221254_smoke`: `marks_before.txt` both present, `DIALOG ... buttons=['OK']`, `DIALOG_DISMISSED OK`, menu ready 19.6 s after the lobby line, `RESULT DONE`, 8/8 shots, clean exit, **both `.dat` files absent afterwards**. Run `20261118_221735_smoke`: full dialog text read, then `FAIL_NOPAWN` + `Alt+F4` clean exit, both `.dat` absent. The `FAIL_LOBBY` branch uses the same `clean_exit`; `FAIL_DIALOG` UNTESTED.
- **Rule (user, 2026-11-19): every stalled or failed run explains itself first.** Before reporting a failure, retrying or killing the game (`FAIL_*`, a quit that does not take effect, the 60 s `FORCED_KILL`), the harness (`autotest_driver.py save_stall(out, reason)`) saves `shots/stall_<reason>.png` (full desktop without focusing the game, `shot_nofocus`) and `windows_<reason>.txt` (every visible top-level window of the game process: class, title, child control texts via `WM_GETTEXT`, rect). Read these two files FIRST in any stalled run, before forming a theory. Reasons: `lobby`, `dialog`, `nopawn`, `menu`, `quit`, `focus`, `exception`, `lua_load`, `forced_kill` (`autotest.sh force_kill()` calls driver subcommand `windows forced_kill <OUT>`). Stall paths other than the happy path: UNTESTED in game (the `windows` subcommand tested offline).
- **Dead ends**
  - FAILED (2026-11-18): "stale GameInput service state, needs a reboot": the reboot only helped because the tester answered the dialog. Never touch `GameInputRedistService` / `gamingservices`. Blocked launches 2026-11-18 20:11-20:28 (4) and 21:01 (`20261118_210120_smoke`, FAIL_LOBBY after 244 s) were wrongly logged as a GameInput fault; they cost ~1 h and a reboot.

## Launching through Steam (2026-11-22)
- `src/tools/launch_game.sh` starts the game as `steam.exe -applaunch 1962700 <args>` (path from `HKCU\Software\Valve\Steam\SteamExe`, fallback the running steam.exe). Steam starts the root launcher `Subnautica2.exe`, which spawns `Subnautica2-Win64-Shipping.exe`, i.e. a launch like pressing Play. **VERIFIED (2026-11-22, run `20261122_112323_sn2world`):** the game reached the menu, no Steam dialog, the Shipping command line in `Subnautica2.log` contains only `-windowed -ResX=1920 -ResY=1080 -WinX=0 -WinY=0`, no `-OverridePlayerStart`.
- Default start override is NONE. `SN2_START=<Tag> bash src/tools/launch_game.sh` adds `-OverridePlayerStart=<Tag>` (Shallows = intro skipped, empty hotbar). The heavy lock (exit 4) and the windowed args are unchanged. `relaunch_on_exit.sh` goes through `launch_game.sh`.
- **`ensure_steam <timeout_s>`** (`src/tools/autotest_lib.sh`; used by `launch_game.sh` and the `autotest.sh` precheck, both modes): logs whether Steam was already running or was started. If `steam.exe` is not running it starts it minimized (`steam.exe -silent`) and waits up to `SN2_STEAM_WAIT` s (default 90) for `HKCU\Software\Valve\Steam\ActiveProcess` `ActiveUser` != 0. Not ready = exit 6 with the lock released, no fallback. **VERIFIED (2026-11-22, offline):** with Steam running it returns at once ("ensure_steam: Steam already running (logged in)"); the refusal works with `SN2_FAKE_NO_STEAM=1 SN2_STEAM_WAIT=4`. The START path is **UNTESTED**.
- Timeouts raised for the Steam path: `autotest.sh` menu-seen limit 180 -> 300 s, driver lobby wait 180 -> 300 s (first menu FPS ~1 while shaders/launcher settle; no fixed sleeps added).
- **Dead ends**
  - FAILED (2026-11-22): `steam://rungameid/1962700` and `steam://run/1962700//<args>/` do not pass launch arguments (see `research/sn2/README.md`). Starting `Subnautica2-Win64-Shipping.exe` directly without Steam gave "not launched through the launcher".
- **Old direct launch (git b949409):** PowerShell `Start-Process Subnautica2-Win64-Shipping.exe -WorkingDirectory <GameDir>\Subnautica2\Binaries\Win64` with env `SteamAppId=1962700`, `SteamGameId=1962700`; works while the Steam client runs. Steam `-applaunch` always starts on the user's desktop, so a hidden-desktop run starts the exe directly through `hidden_desktop.launch_on_desktop`.
