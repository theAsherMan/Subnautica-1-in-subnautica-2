## GC-watchdog diagnosis tools (2026-11-23)
- **`--vt-prio N` (2026-11-26; setup crash fixed, VERIFIED run `20261126_181446_gc_ab_ON_1` VT_PRIO_OK; the three earlier boot crashes were an unguarded `FindFirstOf("PlayerController"):GetWorld()` in vtprio.lua, see `research/crashes/gc_watchdog_renderpipe_2026-11-25.md` H8 "Setup attempts"):** `gc_ab_test.sh --arm ON --ioq --until-crash --runs 5 --timeout 120 --vt-prio 3` writes `<SN2Census mod dir>/vtprio.flag` (line 1 value, line 2 run folder) before launch and removes it after each run and in cleanup. `SN2Census/Scripts/vtprio.lua` (required from main.lua with pcall; inert without the flag) sets `r.VT.IOPriority_HighPagePri` through `KismetSystemLibrary:ExecuteConsoleCommand` (retry every 0.5 s on the game thread) and logs the `GetConsoleVariableIntValue` read-back to `<run>/vtprio.txt` (lines `<epoch> armed|try|SET_OK|LOADMAP_PRE|LOADMAP_POST readback=N world=...`). After the run the harness writes `vtprio_verdict.txt` + `vt_prio_verdict=` in `run_info.txt`; VT_PRIO_SETUP_FAIL (no SET_OK, or a LoadMap pre-hook read-back differing after it) appends to the classification and stops the series. Why Lua: all command-line cvar routes are compiled out in Shipping (see research/crashes/gc_watchdog_renderpipe_2026-11-25.md, "Fix 1 route analysis").
- **Diag mode (2026-11-24, VERIFIED: ran in 3 runs, census files written):** `gc_ab_test.sh --arm ON --diag` (max 3 runs; stops after 1 crash + 1 purge >= 10 s) writes `<SN2Census mod dir>/diag.flag` (first line = run folder, forward slashes) before launch and removes it afterwards; passes `-LogCmds="LogGarbage Verbose" -trace=cpu,frame,log -tracefile=<run>/gc.utrace` (both ineffective in Shipping, see research/crashes/README.md). `src/mods/SN2Census/Scripts/diag.lua` (required from SN2Census main.lua with pcall) is inert without the flag; with it: lobby baseline census 10 s after the lobby LoadMap and a `pre_travel` census in `RegisterLoadMapPreHook` when the current world is L_ClientLobby; writes `census_<label>.txt` (top 30 classes, SphereComponent/BodySetup/top-5 split by world / outer / outermost with `HasAnyFlags` masks, 20 SphereComponent samples) and echoes the head to UE4SS.log with prefix `[SN2Census] diag`. Cost ~0.6 s + 1.9 s. `src/tools/gc_window.py <Subnautica2.log> [out]` prints the LoadMap to SkyLight window (`purge_window.txt`). Lua checked by read-through plus the in-game load only (no lua/luac installed).
- **Thread sampler tools (2026-11-24, VERIFIED on a test process and on one game run):** `src/tools/gc_thread_sampler.py <out.tsv> [--exe NAME] [--pid N] [--interval 0.1] [--max-seconds 150]` (run WITHOUT `-I`: psutil is in the user site) reads `NtQuerySystemInformation(5)` every 100 ms for every thread of the game: columns `utc, epoch, tid, name (GetThreadDescription), user_100ns, kernel_100ns, cycles, state, wait_reason, ctx`; read-only (no suspend, no debugger). `src/tools/gc_thread_window.py <run>` (stdlib, `-I` fine) takes the LoadMap L_SN2World to SkyLight window of `<run>/Subnautica2.log` and prints per-thread CPU % in the window and the 10 s before, a per-second timeline of GameThread/RenderThread/RHIThread with state or wait reason, the top 5 other threads and the dominant states (KWAIT_REASON decode table inside). `gc_ab_test.sh --diag` now caps at 4 runs, starts the sampler after launch (killed after the run), writes `nocensus` as line 2 of diag.flag (diag.lua then skips all census work), writes `<run>/thread_window.txt`, and stops after the first purge >= 10 s or crash with more than 1000 samples. About 20 MB of samples per run.
- **Stack sampler tools (2026-11-24; sampler VERIFIED on a busy python process: 80 samples at 20 Hz, RIP always in python312.dll, max suspension 0.09 ms, process still 100 % CPU afterwards = resumes pair; analyser VERIFIED offline on the game exe):** `src/tools/gc_stack_sampler.py <run dir> --log <live Subnautica2.log> [--hz 20] [--max-sample-seconds 25] [--max-seconds 200]` (run WITHOUT `-I`) waits for the game, tails the live log, on `LogLoad: LoadMap:` with `L_SN2World` suspends the thread named GameThread at 20 Hz (OpenThread SUSPEND_RESUME|GET_CONTEXT|QUERY, SuspendThread, GetThreadContext CONTEXT_FULL 16-byte aligned, ReadProcessMemory 64 KB from RSP, ResumeThread in `finally`) until the first `SkyLight change`, 25 s or game exit. Writes `stack_samples.jsonl` (regs, per-sample suspension ms, and `objs` = 32 bytes read AFTER resume at every pointer-like register / first 64 stack qwords), `stack_samples.bin` (raw stacks), `stack_modules.json` (module bases), `stack_sampler.log`. Test options `--now --tid N --pid N`. `src/tools/gc_stack_analyse.py <run>` (stdlib, `-I` fine; reads the exe on disk, no PDB): PE sections, `.pdata` RUNTIME_FUNCTION table (chained unwind entries folded into the parent, 668k functions, 1.3 s), RIP-in-function histogram, call-preceded return-address histogram (% of samples), strings referenced via RIP-relative LEA/MOV (follows one pointer slot; ASCII and UTF-16LE), sanity check for `routing FinishDestroy`, tier 2 vtable/ClassPrivate (+0x10) histogram resolved through `<run>/classmap.tsv`. `gc_ab_test.sh --stacks` (implies `--diag`, cap 3 runs, no -LogCmds/-trace args, diag.flag line 2 = `nocensus classmap`) starts the stack sampler instead of the thread sampler and writes `stack_analysis.txt`; diag.lua with `classmap` writes `classmap.tsv` (hex UClass address, TAB, class full name, one row per class of any object) and `objaddrs.tsv` 10 s after the lobby LoadMap.
- **All-thread sampling and analyser additions (2026-11-25, UNTESTED in game: both runs of the first series timed out before the world load):** `gc_stack_sampler.py --other-hz N` (default 5, 0 = off) also samples, during the same L_SN2World window, every thread whose name matches RenderThread, RHIThread, RHISubmission, IoDispatcher, AsyncLoad, FileIO, IOThread, LoadingThread, Worker, TaskGraph or ThreadPool (16 KB of stack each), writing `stack_threads.jsonl` + `stack_threads.bin` in the run folder. `gc_stack_analyse.py` adds `thread_report` (per-thread top frames / modules from those files) and `gamethread_this_class` (class of the `this` object (RCX) at the ready-check callees 0x4605AF0 / 0x41AD070; LOGGED on run `20261124_192400_gc_ab_ON_3`: 0x4605AF0 Object 92 / StaticMesh 60, 0x41AD070 Object 27 / MaterialInstanceConstant 18), and exits 0 with a message when `stack_modules.json` is missing (0-sample run). `gc_ab_test.sh --noflush` skips the standby-cache flush (warm boot) and writes `flush_mode.txt`; timeout unchanged (120 s). `--stacks` series (2026-11-25): cap raised 3 → 8 runs; a slow-load TIMEOUT (classification `PASS_TIMEOUT_LOW`) does not stop the series, a `CHECK` run does (since 2026-11-25 a TIMEOUT is `CHECK` only when the timeout shot's window list `timeout_screen.png.windows.txt` has a `#32770` dialog of the game pid; the old rule "driver.log mentions overlapping windows" misfired on the benign UE4SS Debugging Tools window in run `20261125_161952`), and it stops once a purge >= 10 s or a crash has >= 100 GameThread samples.
- **Disk/IO counters in `--stacks` diag runs (VERIFIED 2026-11-25, run `20261125_175756_gc_ab_ON_1`: 124 disk rows, 120 process rows):** `gc_ab_test.sh` starts two read-only `typeperf` loggers right after launch (1 Hz, 200 samples max, killed at run end and in the EXIT cleanup): `disk_perf.csv` (`\PhysicalDisk(*)\` Current Disk Queue Length, % Idle Time, Disk Reads/sec, Disk Read Bytes/sec, Avg. - **IoStore request scanner + mapper (2026-11-26, VERIFIED in 5 game runs; H8):** `gc_ab_test.sh --ioq` (implies `--stacks`; runs the scanner INSTEAD of the stack sampler, plus the typeperf disk/IO loggers; with `--until-crash` it stops on the first CRASH/CHECK) starts `src/tools/gc_ioq_scan.py <run dir> --log <live game log> --full-every 3 --max-seconds 150` (run WITHOUT `-I`: psutil + numpy). Read-only (`ReadProcessMemory` of resident MEM_PRIVATE pages only, below-normal priority). It waits for `--gate` (default: the first mod container mount `in location slot 1`, ~3 s after launch, or `LogInit: Display: Starting Game.`), finds the `FFileIoStoreContainerFilePartition` structs through their `.ucas` path strings, then in a thread repeats full scans (also re-finding partitions and strings) while the main loop re-reads only the 64 KB blocks that held requests (+-2 neighbours) every 0.5 s. Output: `ioq_scan.jsonl` (per fast scan: queued / started / done counts, queued MB, `prio` histogram), `ioq_life.json` (per request sequence: raw offset, size, priority, partition path id, creation QPC, first-seen queued / started / done, last-seen queued), `ioq_parts.json` (QPC frequency + partition paths; a request row stores an index into `paths`), `ioq_scan.log`. Struct layout and the way it was verified: `research/crashes/gc_watchdog_renderpipe_2026-11-25.md`, "H8 series". `src/tools/gc_ioq_map.py <run dir>` (stdlib + numpy, `-I` fine; `local.config` for the game dir; runs `retoc list --all --package --size --path` once and caches `utoc_list.txt`) writes `ioq_report.txt`: queue timeline relative to the L_SN2World `LoadMap`, requests grouped by first-seen-queued before / during the purge with raw MB per chunk type and top packages, queue-wait stats, and a "stall model" section (BelowNormal queue at the travel and the moment it first reads empty vs the purge end). The same file has a TOC parser class `Toc` (`attrib(offset, size)` = chunk indices and compressed bytes for a raw .ucas range). Known limit: `--probe` dumps raw candidate structs; request rows whose partition pointer is stale are dropped.
- **Sampler stack-read fix and CPU/thread logging (2026-11-25; VERIFIED on a dummy python process with named threads, NOT yet in game).** Changes in `gc_stack_sampler.py`:
  - **Stack reads:** `read_stack(hproc, rsp, buf, cap)` first tries one full read. If that fails, it reads page by page up to the first unreadable page (found with `VirtualQueryEx`) and returns the byte count. This replaces the old 16K/8K/4K/1024 fallback, which lost the outer frames of short stacks such as the render thread's (about 2.5 KB).
  - **Thread selection and stack size:** `RHIInterrupt` was added to the thread-name regex. `DEEP_RE` (RenderThread, RHIThread, RHISubmission, RHIInterrupt) threads get 64 KB stacks; the other threads get 16 KB.
  - **Region logging:** on the first sample of each thread, `stack_sampler.log` gets a line `stack region <name> rsp=.. len=.. region=base+size st= pr= ab= next=...`.
  - **New output `stack_cpu.jsonl`:** one line per sweep, `{"t", "sweep", "th": {tid: [user, kernel, state, waitreason, ctxswitches]}}`, for ALL threads of the game process. Times are in 100 ns units.
  - **New output `stack_thread_names.json`:** a map from tid to thread name.
  - **Dummy test:** RenderThread 3256 bytes, Foreground Worker 3560, RHIInterruptThread 2136 (all full stacks; the old code read only 1024); 0 failures; max suspension 0.268 ms.
  - **In game (VERIFIED 2026-11-25, run `20261125_172429_gc_ab_ON_1`):** `stack_cpu.jsonl` 72 sweeps, `stack_threads.jsonl` 2808 rows, full render-thread stacks. Gaps: the GameThread tid is only in `stack_sampler.log` ("GameThread tid N"), not in `stack_thread_names.json`; some busy threads have no name (e.g. tids 12996, 10364 in that run).
  - **Pipe logging (H6):** `stack_globals.jsonl` logs the render command pipe (`prod`, `q0`/`q1`, the command names). It is described in `research/crashes/gc_watchdog_renderpipe_2026-11-25.md`, "Render command pipe (H6)".
- **Static fact (VERIFIED 2026-11-24, exe on disk):** the string `Spent more than %.2fs on routing FinishDestroy to objects (objects in queue: %d)` lives in .rdata behind a pointer slot referenced from the function at RVA 0x15B5330 (the incremental-purge function: also references `Not destroying garbage because GAllowSkipDestroyGarbage==1 && GSkipDestroyGarbage==1 (per obj loop / outer loop)`, `Spent too much time waiting for FinishDestroy for %d object(s) (last object: %s), check log for details` and `%.3f ms for incrementally purging unreachable objects (FinishDestroyed: %d, Destroyed: %d / %d)`); it is called from RVA 0x15B5BA0.
