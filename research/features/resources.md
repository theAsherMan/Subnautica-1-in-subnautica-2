## Resources / flora
World-pop resources: `BP_WorldPopSpawnedTitanium_C`, `…Quartz_C` etc. are placed by the zone system; hand placement via `BP_ResourceDeposit_<Mineral>_C` and `BP_ResourceNode_<Mineral>_C`
(Titanium, Copper, Quartz, Lead, Sulfur, Gold, Celestine, Lithium, Salt, Silver, Atacamite, Fulgurite, TarGraphene, AxumRebar). Flora Blueprints live under
`Art/Environment/Biome/<Biome>/{Organic,Foliage,Corals}` (e.g. `BP_AcidAnemone_C`, `BP_PomePlant_01a_C`, `BP_Freesia_*`, `BP_CG_CoralDome*_C`) and surface rules in `Data/SurfaceSpawnData`.

**Porting SN1 game elements (user decisions 2026-11-26):**
- SN1 decorations (plants, coral, rocks, doodads) are ported with **SN1's own meshes and textures**, extracted from the user's SN1 install (UnityPy approved), not swapped for SN2 lookalikes.
- SN1 **breakable resources** (limestone / sandstone / shale outcrops, loose quartz, etc.) are ported as **SN2's own breakable resource Blueprints** (`BP_ResourceDeposit_*` / `BP_ResourceNode_*` / world-pop types) at the SN1 position, so they work as game elements from the start.
- **Rule for the future:** where SN2 has no matching resource (e.g. SN1 diamond from basalt outcrops — SN2 has no diamond), build a custom placeholder "resource" that is **very obviously not implemented** (e.g. a loud debug-coloured marker with a "not implemented: <SN1 name>" label), never a silent substitute with a different SN2 resource.

**SN2 side (VERIFIED 2026-11-26: editor probe, cooked-package decode with retoc + UAssetAPI, game data assets read in the editor).**
- Hierarchy: `BP_ResourceNode_<Mineral>_C` -> `BP_ResourceNode_Parent_C` -> native `UWEWorldPopResourceBaseActor` (`bIsBreakingDisabled`, `bHasBeenGathered`, `ResourceId` FGuid, `OnResourceGathered`, `StaticMesh`, `AssetData`). `BP_ResourceDeposit_<Mineral>_C` also derives straight from `UWEWorldPopResourceBaseActor`. Loose items `BP_<Mineral>_C` (BP_Quartz, BP_Salt, BP_Titanium, BP_MetalSalvage...) derive from `/Game/Blueprints/Items/BP_BasePickupItem`; `BP_WorldPopSpawned<Mineral>_C` (Titanium, Copper, Quartz, SilverLoose, GoldLoose, SulfurLoose, LithiumLoose, CelestineLoose) derive from `UWEWorldPopResourceBaseActor` (loose resources tracked by the world-pop system).
- **The yield and the "is breakable" behaviour live in the Blueprint CLASS DEFAULTS, not on the placed instance.** `Default__BP_ResourceNode_Titanium_C` has a `UWEAssetDataComponent` ("AssetData") whose `UWEAssetUserData_0.DataAssets` = [`/Game/Data/Pings/DA_MineralPing`, `/Game/Data/ScanData/Resource/DA_Titanium_ScanData`, `/Game/Data/BreakableData/DA_TitaniumNode_BreakableData`] (decoded from the cooked BP). Deposits point to `/Game/Data/Resonatable/DA_<Mineral>Deposit_ResonatableData` instead. `UWEBreakableStatics`/`UWEAssetRegistryStatics.GetActorDataAssetForActor` find the data asset through that component. `UUWEBreakableData` (native): `Content[]` of `FResourceContent{ResourceClass (item BP), NumResourcesToDrop, DropChance, SpawnImpulse, bAutoPickup, AutoPickupRange}`, `NumHitsToBreak`, `NumHitsToBreakWithTool`, `HitCueTag`, `BreakCueTag`, hit/break stimulus effects (NumHitsToBreak is class-default, not stored in the asset; value unread).
- **Placed instances need nothing else (VERIFIED 2026-11-26, game dev map `/Game/Maps/L_Default_DevMap`, T3D of hand-placed actors in `<Workspace>/reports/sn1res/devmap_*.t3d`):** a hand-placed `BP_ResourceNode_Titanium_C` is just the class + `StaticMesh` RelativeLocation/Rotation (+ tag `AutoBlend_HasPrimitiveData`); the dev map holds 820 Titanium, 527 Copper, 491 Silver, 70 Quartz nodes, 1 Salt/Celestine, 2 Sulfur, deposits (Titanium 2, Salt 1, AxumRebar, NeedleSharkNeedles, DeepRoot) and 1,656 `BP_WorldPopSpawnedTitanium_C`. No instance carries a `ResourceId` line.
- Drop tables (read in the editor from the cooked `DA_*_BreakableData`, VERIFIED 2026-11-26): Titanium node = 3 x Titanium at 100 %; Copper/Lead/Salt/Quartz/Silver/Gold/Sulfur node = 3 entries of 1 item (100 %, 100 %/40 %, 50 %/25 %); Lithium node = 4 entries; each node yields ONE mineral type. Deposits (resonatable): Titanium/Copper/Lead/Gold/Silver/Salt/Quartz 5 x item at 100 %, Sulfur 2+1+1, Lithium 1+1, Celestine 1+1+1, Atacamite 3+1+1, TarGraphene 2+1+1, Fulgurite ConduitCrystal 1+1+1. Nodes break by hits (breakable); deposits are the bigger "resonatable" kind (extra ability component on Lithium).
- Spawned meshes (editor probe): nodes ~1 m (Titanium `SM_Resource_TitaniumNode_02b`, extent 52 x 50 x 44 cm; Salt `SM_Resource_SaltNode_03a`; Quartz `SM_Resource_QuartzNode_02b`; other minerals 45-56 cm), deposits 1.3-1.7 m half extents. Collision `BlockAllDynamic`, mobility MOVABLE on spawn.
- SN2 has NO non-deprecated Diamond, Nickel, Magnetite, Kyanite, Uranium or Obsidian: `Blueprints/Items/Resources/Deprecated/BP_Diamond`, `BP_Nickel`, `BP_Tungsten` exist as classes but are deprecated items (not probed). There is no `BP_ResourceNode_Lithium` in `World/ResourceNode` (only `BP_ResourceDeposit_Lithium` and `GameplayCueNotifies/ResourceNodes/Lithium/BP_ResourceNode_Lithium_Destructible`, `DA_LithiumNode_BreakableData`; the destructible BPs were not probed).

**Placement recipe (editor Python, VERIFIED 2026-11-26 in `L_SN2World`: spawn, save, reload from disk, identical read-back, delete, save):**
```python
cls = unreal.load_class(None, "/Game/Blueprints/World/ResourceNode/BP_ResourceNode_Titanium.BP_ResourceNode_Titanium_C")   # cooked BPs are classes, not assets
a = unreal.get_editor_subsystem(unreal.EditorActorSubsystem).spawn_actor_from_class(cls, unreal.Vector(x_cm, y_cm, z_cm), unreal.Rotator(0, yaw, 0))
a.tags = ["SN1Res", "SN1Res_limestone"]; a.set_actor_label(f"SN1Res_limestone_{i}"); a.set_folder_path("SN1Res")
# idempotent re-run: destroy every actor whose tags contain "SN1Res" first, then unreal.EditorLoadingAndSavingUtils.save_current_level()
```
Notes: `unreal.load_asset("/Game/Blueprints/World/ResourceNode/BP_ResourceNode_X")` returns None (the cooked BP is not a loadable Blueprint asset in the modkit; only the generated class loads). No properties need to be set: mesh, collision, data assets, scale all come from the class defaults; the readback after reload matched exactly (25 actors, mesh paths, bounds, collision profile). Pitfall: `BP_ResourceDeposit_Sulfur_C` spawns with scale (-3,-3,-3) and bounds extent 19.6 km (prototype quirk): do not use. Scale per SN1 instance: set actor scale; for nodes the SN1 mesh ~0.9 m wide vs SN2 ~1 m, so scale 1 is fine.
