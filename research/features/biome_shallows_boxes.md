## Safe Shallows -> SN2 box regions (transfer plan, 2026-11-24)
- Tool: `python -I src/tools/sn1_biome_transfer.py <biome> [--cell 32] [--overlap 10] [--min-px 100] [--y-top 5] [--y-bottom -200] [--settings <waterbiomes dump>]`
  (offline, numpy, no heavy lock). Reads `<SN1Dir>` Build18 `biomeMap.bin` + `biomes.csv`, keeps 4-connected components >= `--min-px`, rasterises them to
  `--cell` m cells (a cell is in if >= half its pixels are the biome), covers the cells with a greedy exact rectangle cover, grows each rectangle by
  `--overlap` m per horizontal side, and writes `<Workspace>/sn1_biomes/<biome>.json`: `boxes[{unity_x, unity_z, unity_y, center_ue, half_ue}]`
  (UE cm, map offset 0), `mask_px`, `miss_px`, `extra_px`, and with `--settings` the SN1 settings, the converted `water_light` dict and `water_light_t3d`.

- Conversion formula v1 (UNTESTED, needs screenshot calibration; the modkit has no UWEWater shaders, see `research/features/README.md`): sigma_c = SN1 `derived_extinction_per_m`;
  `BiomeExtinction_c = exp(-sigma_c * K_M)` (K_M = 1); `BiomeExtinctionSkylight_c = LMAIN_SKY_c ** (sigma_c*K_M / -ln LMAIN_DIR_c)` (L_Main's ocean ratio kept);
  `BiomeAlbedo` = scattering_rgb / sigma normalised to max 1; `WaterFogDistance = 100 * 3 / mean(sigma)` cm clamped to [1000, 20000];
  `Advanced.BiomeEmissive` = SN1 derived emissive if non-zero; scales 12.5/17.5, fog thickness 10/4, blend XYSeperateZ (2000,100), DepthFadeMax 45000 kept from L_Main.

    - **Mechanism. VERIFIED (2026-11-27, UE4SS.log `UWPROBE uw REGION ... MAT` lines + cooked L_Main export).** The look of a water region is its `WaterStaticMeshComponent` (`/Engine/EngineMeshes/s_cube_1cm`, a huge cube) drawn with a MID of `MI_OceanVolume`.
      - In L_Main that MID, `MI_OceanVolume_Biome_BPDefined_0`, is a SERIALIZED sub-object of the cooked map (export in `<ModkitDir>/scratch_bp/lmain_json/L_Main.json`, class MaterialInstanceDynamic, outer = the region component): 13 scalar parameters (`BiomeExtinctionDistanceDirectionalLight` 12.5, `...Skylight` 17.5, `WaterFogDistance` 7500, `WaterFogThickness` 10, `BaseWaterFogThickness` 4, `WaterFogOpacityWeight` 1, ...), 6 vector parameters (`BiomeExtinctionColorDirectionalLight` = `...Skylight` = (0.907,0.945,0.955), `BiomeAlbedo` (0.1,0.295,1), ...) and `BasePropertyOverrides.BlendMode = BLEND_TranslucentGreyTransmittance`.
      - In L_SN2World every region (the ocean's CAT_0, the standalone `BP_UWEOceanBiomeRegionActor_C_1`, all 42 SN1 boxes) has a generic runtime MID `MID_MI_OceanVolume_<n>` with only 2 scalars (`CurrentWaterBodyIndex`, `CurrentWaterBodyBlendType`, written by the biome tracker).       - The MID is created by the native `AUWEWaterBiomeRegionActor::RecreateMaterials` (Headers.hpp; the modkit C++ is a stub, no UWEWater code). The Blueprint calls it only from `UserConstructionScript` (cooked bytecode of `BP_UWEOceanBiomeRegionActor`: `ReceiveBeginPlay` only calls the parent's, `UserConstructionScript` = parent + `RecreateMaterials`). In the game the construction script runs in the editor and the resulting MID is saved into the level. A cooked placed actor does not re-run it. In our modkit editor the stub does nothing, so nothing is baked; at runtime nothing recreates it. Why `WaterLightSettings` on the regions "has no effect" (2026-11-26) is therefore explained: the values are never pushed into the material.
